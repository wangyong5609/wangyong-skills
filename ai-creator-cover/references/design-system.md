# 影视飓风封面拆解 → 主理人皮肤规范（v2）

来源：`影视飓风数据.xlsx`，57 张封面，本地存于 `downloads/yingshi-hurricane-covers/`，联系表见 `assets/contact-sheets/`。

本文件回答两个问题：影视飓风的封面团队**到底在做什么**；本 Skill 的皮肤**如何结构等价地替换**他们的品牌层。

> 配置边界：第一、三节的结构定律和 tokens 对所有使用者锁死；第二节替换表中的品牌项（强调色、标签文案、人脸）取自 `profile.md`，每个使用者配置自己的。

## 一、他们在做什么：设计师视角拆解

影视飓风老板说过：项目立项第一件事是先做封面，一个选题做几十甚至上百版再选最好的。所以这 57 张封面是经过市场验证的幸存者，共性极强。

### 1. 骨架：两区结构（最重要的发现）

几乎每张封面都是同一个骨架：

- **顶部 22-35% 是纯黑/深色平面信息栏**，所有标题文字都在栏内。文字永远压在纯色底上，从不压在杂乱画面上——这是手机信息流缩略图可读性的根本保证。
- **下方 65-78% 是照片区**，装在红色圆角框这个"容器"里。

文字区和照片区**物理隔离**。这一条解释了为什么他们的封面缩到拇指大小依然能读。

### 2. 容器装置：红框是结构件，不是装饰

红色圆角框把照片"装"起来，而人物经常**突破框沿**——头顶出框、手伸出框、产品怼到镜头前压住框线。突破制造了三层深度：框后的照片 → 框 → 框前的人物。这是"正在被录制"临场感的来源。

> v1 的教训：去掉 REC/红点是对的（那是他们的品牌标识），但红框这个**结构件**被一起丢掉且没有替代品，画面就散了。v2 用黄框做结构等价替换。

### 3. 照片层：真实摄影，不是渲染

他们的照片是真的拍出来的，特征：

- 现场光/环境光为主，常见暖色调，不是棚拍硬光
- 浅景深，主体锐、背景虚
- 手里有**真实道具**：相机、手机、产品、食物
- **抓拍表情**：咬披萨、皱眉看屏幕、大笑、惊讶回头——是"瞬间"不是"姿势"
- 电影感调色 + 轻微颗粒
- 照片区色彩丰富（米色卫衣、彩色色轮、金色手机壳、蓝天），与纯黑信息栏形成强对比

### 4. 字体排印纪律

- 超粗紧凑黑体（综艺标题字），字重 800-900
- 每行 4-7 个字，最多 2-3 行
- **句内换色**：白色句子里只有 2-3 个关键字换成黄/红色。不是单独放一个巨大斜体词
- 标点是设计元素：问号出现频率极高
- 句式：疑问句、数字句、反常识句、产品名句

### 5. 信息极简

一张强封面 = 标题（≤2行）+ 照片 + 也许 1 个箭头/圈注。没有功能清单、没有多个 UI 面板、没有底部收益条。"只让用户先记住一个词"。标题不是视频标题的复刻，而是压缩出一个冲突点或悬念点。

### 6. 表演多样性

57 张封面里几乎没有重复的人物表演：双手举起拒绝、抛接乒乓球、手持产品展示、穿盔甲奔跑、捂头惊讶、戴墨镜坐姿、递照片给镜头、举牌、趴桌开箱、端咖啡……动作、表情、景别、场景每张都不同，重复的只有脸和皮肤结构。**IP 感 = 固定身份 × 永不重复的表演**。这条定律的执行机制见 `performance-library.md`（表演库 + 反重复规则）。

### 7. 例外情况

发布会、短片、招聘类封面会放弃录制框架，转为海报/摄影作品（如纯剪影、纯产品）。这类占比小，v2 不做默认支持。

## 二、主理人皮肤：结构等价替换表

| 影视飓风（品牌层） | 结构作用 | 主理人替换（取自 profile.md） |
|---|---|---|
| 左上红色录制点 + 右上 REC | 固定身份标识 | 左上角分类标签（品牌色竖条 + 白字） |
| 红色圆角框 #E60023 | 照片容器、突破对象 | 品牌色圆角框（默认 #F5C518 亮黄） |
| 红/黄混用强调色 | 句内换色 | 统一只用一个品牌色 |
| 团队成员出镜 | 真人主角 | 主理人人脸库（或无人脸模式的实物主角） |
| 相机/数码产品道具 | 证据物 | 手机/键盘/屏幕一角/AI 工具界面局部 |

**不变的结构定律**（直接继承）：两区结构、容器突破、真实摄影感、句内换色、信息极简。

## 三、皮肤 tokens

```yaml
canvas:
  ratio: "3:4"
  output: ["1080x1440", "1290x1720"]

colors:
  bar_black: "#0A0A0A"        # 信息栏，平面无纹理
  brand_accent: "#F5C518"     # 框、标签竖条、换色字，全皮肤唯一强调色；取自 profile.md，#F5C518 是默认值
  text_white: "#FFFFFF"
  photo_zone: "继承真实环境色，鼓励丰富"

structure:
  top_bar: { height: "22%-30%", content: "标签 + 标题，仅此而已" }
  frame:
    color: "#F5C518"
    corner_radius: "画面宽度 3%-4%"
    stroke_width: "画面宽度 1.5%-2.5%"
    inset: "左右 4% 安全边距，下沿到画面底（或留 2%）"
  breakthrough: "人物头部或手必须越过框上沿进入信息栏区域，可轻微压住标题底部笔画，但不遮挡可读性"

typography:
  title: { weight: 900, chars_per_line: "4-7", lines: "1-2", size: "字高约画面宽度 9%-13%" }
  emphasis: { mode: "句内换色", chars: "2-4", color: "#F5C518" }
  tag: { width: "14%-18% 画面宽度", style: "黄竖条 + 白色粗体字" }

photo_direction:                # 摄影指导，写进提示词
  lighting: "现场光/暖色环境光，避免棚拍硬光和戏剧性轮廓光"
  depth: "浅景深，人物锐利背景虚化"
  grade: "电影感调色，轻微胶片颗粒"
  moment: "抓拍：动作进行中或反应瞬间"
  prop: "一个真实物件在手里或身边"
  environment: "真实环境：工作桌、屏幕前、室内场景，有环境色"
```

## 四、v1 失败原因归档（防止回退）

对照 v1 产出（已删除）与原版的差距，沉淀出以下教训，重构后必须避免：

1. 标题直接压在代码墙/桌面背景上 → 违反两区结构
2. 无容器框 → 元素漂浮
3. AI 海报感：完美打光、机械暗黑背景、摆拍表情 → 违反真实摄影定律
4. 塞任务清单、多面板、底部小字（v1 的 01、04 号）→ 违反信息极简
5. 单独巨大斜体黄词 → 违反句内换色
6. 虚构完整 UI 面板做证据 → 看起来假；证据必须是实物或真实截图局部
