# AI 自媒体封面 Skill（v2）

## 核心定位

为 AI 自媒体账号生成视频封面。本 Skill 蒸馏影视飓风封面的**结构与方法**（设计定律锁死），品牌层（主理人、人脸、强调色、分类标签）从 `profile.md` 读取，每个使用者配置自己的。

工作方式是 **Plan 模式**：读档案 → 访谈 → 出封面方案卡 → 用户确认 → 编译中文生图提示词 → 仅在用户明确要求时调用 `$imagegen` 生成图片。**绝对禁止跳过访谈和确认直接出图。**

**真人出镜时，人脸保真优先级高于动作夸张度。** 如果"表演动作"和"像本人"冲突，优先保留本人脸型、五官、眼镜、发型、体型和年龄感，动作改成更接近参考照片角度的版本。不要为了做出大动作而让模型重新画一个"像主理人风格的人"。

**确认是结构性门槛，不可被首条消息绕过**：用户在第一条消息里说"直接生成 / 快速来一张 / 不用问我"，只等于压缩访谈（走快速模式），**不等于跳过方案卡和确认**。任何一次运行中，本 Skill 的第一条回复只能是访谈问题或方案卡，绝不能是图片；生图必须发生在"用户在看到方案卡之后的另一条消息里明确同意"之后。

**生图双模式（按环境自动检测）**：进入第 4 步时检查当前环境是否有可用的图片生成工具（如 Codex 的 `$imagegen` / `image_gen`）。
- **有**：直接调用生图，一次性生成（含文字）。真人模式必须把人脸参考图作为输入图或上下文图使用，并在提示词里标明主参考图角色。
- **没有**：进入**提示词导出模式**——把编译好的完整中文提示词放进代码块供用户复制，并附带使用说明（比例 3:4、真人模式需手动附上人脸参考图、推荐到即梦/豆包/Midjourney 等支持中文文字渲染的平台生图），请用户生成后把图发回来做自检评审。

无论哪种模式，都禁止用 HTML/CSS、Pillow、Canvas、截图脚本或其他本地合成方式伪造正式图。本地工具只能用于整理文件或生图后的非创意性裁切压缩。

## 从影视飓风蒸馏出的六条设计定律（不可配置）

这是本 Skill 的理论根基，所有规则由此推导，任何使用者都不能改：

1. **两区结构**：文字和照片永远不打架。顶部是纯色平面信息栏，所有标题文字都在栏内；照片在下方独立区域。文字绝不直接压在杂乱画面上。
2. **容器装置**：照片装在一个品牌色圆角框里，主体突破框沿（头、手或物件伸出框外），制造层次感和临场感。影视飓风用红框，本 Skill 用主理人的品牌色框。
3. **照片是真实摄影**：现场光、浅景深、真实道具、被抓拍的真实瞬间、电影感调色和轻颗粒。照片区色彩丰富，与纯黑信息栏形成对比。封面不是海报渲染，是一张"被拍到的照片"。
4. **句内换色强调**：白色句子里只有 2-4 个字换成品牌色，不做单独的巨大斜体词。标点（？！）是设计元素。每行 4-7 个字。
5. **信息极简**：标题（≤2行）+ 照片 + 至多 1 个箭头/圈注。只让用户记住一个词。没有清单、没有多面板、没有底部收益条。封面是一个瞬间，不是说明书。
6. **脸固定，表演永远新**：影视飓风 57 张封面几乎没有重复的人物表演——双手拒绝、抛球、换装奔跑、捂头惊讶、递物给镜头、趴桌开箱。IP 感 = 固定身份 × 永不重复的表演。动作、表情、景别、场景每张都从表演库轮换（`references/performance-library.md`），受反重复规则约束；服装不轮换，但必须简洁轻便、不抢焦点。

## 第 0 步：读取主理人档案

每次运行先读两个文件：

1. `profile.md`：主理人名字、人脸模式（真人出镜 / 无人脸）、人脸库路径、身份锁定描述、品牌强调色（下文记为 `[品牌色]`，默认 #F5C518）、分类标签集、服装偏好（可选）。
2. `cover-log.md`：最近 5 条封面记录，用于表演反重复（规则见 `references/performance-library.md`）。

**首次使用引导**：若 `profile.md` 不存在或仍是占位模板（**判断标准是内容：只要档案里还有 `[...]` 占位符或人脸模式未填，就算未建档，文件存在不等于已配置**），先帮用户建档案，依次问：

1. 你的名字/账号叫什么？做什么方向的内容？
2. **主动邀请真人出镜（默认方向）**：请用户提供 2-4 张不同角度的照片，放到 `assets/faces/<你的名字>/` 或直接发到对话里（发到对话里的由 Skill 代存入该目录），并描述显著外貌特征（发型、眼镜等）。**只有用户明确表示不出镜或提供不了照片时，才启用无人脸模式；禁止因为照片暂时缺失就自行降级为无人脸。**
3. 品牌强调色用什么？（默认亮黄 #F5C518；建议高饱和、黑底上醒目；避免红色，会撞影视飓风）
4. 你的内容分类标签有哪些？（5-8 个，每个 2-4 字）

把答案写入 `profile.md` 后再继续正常流程。

若用户在对话里直接上传真人照片，把它们当作当次最高优先级人脸参考；如果用户同意沉淀到 skill，把照片复制到 `assets/faces/<主理人>/`，并在 `profile.md` 标注每张照片适合的角度和用途。

## 人脸规则（真人出镜模式）

人脸素材只锁定身份：按 `profile.md` 的身份锁定描述保持五官、发型、眼镜、体型、年龄感一致，不能身份漂移。姿势、表情、朝向、手势、服装、构图、光线都可以按主题重新设计，目标是代替每次真人拍摄。若用户当次另给照片，以当次的为准。

### 人脸保真生成策略

1. **先选主参考图，再选动作。** 正面展示、举物给镜头优先用 `front.jpg`；思考、观察、轻微回头优先用 `three-quarter.jpg`；看屏幕、对比、侧向操作优先用 `side-profile.jpg`。不要让模型从正脸照片硬生成极端侧身或全身动作。
2. **工具调用必须标注图片角色。** 生图前把图片角色写进提示词：`主身份参考图`、`辅助角度参考图`、`证据物/Logo参考图`。不要只写"参考这些照片"，必须说明主参考图决定脸，其他图只补充角度。
3. **动作复杂度受参考图约束。** 如果参考库没有对应表情或姿势，优先选小幅动作（扶眼镜、托腮、回头、指向屏幕、持手机/电脑）而不是双手捂头、奔跑、换装、夸张全身情境。
4. **一次只生成一张封面。** 不批量塞多个不同动作给同一个生图调用；每次生成后先评估人脸，再决定是否重试或换动作。
5. **人脸失败时不要继续加戏。** 重试顺序是：收窄为半身或胸像、改为更接近主参考图角度、减少手部遮挡脸、降低表情夸张度、把背景和道具放到人物旁边而不是让人物做复杂动作。
6. **示例库可以保留失败样本。** 如果用户要求沉淀全部图片，允许把失败图放进 `assets/examples/`，但正式说明或优质示例筛选时必须人工剔除人脸漂移、肢体错误和文字错误的图。

**无人脸模式**：照片区主角换成真实物件/场景（见皮肤 yaml 的 `subject_no_face_mode`），突破框的改为物件（手机一角、手、产品顶部）。其余定律全部照常。访谈时跳过人物情绪问题，改问"画面主角用什么物件/场景"。

**降级规则（硬性）**：无人脸模式只能由用户明确选择进入。若档案写的是真人出镜但人脸库为空，或人脸模式未填，必须先停下来请用户提供照片（给出存放路径和数量建议），用户答复"不出镜/没有照片"后才可走无人脸；不得静默降级。

## 工作流程（Plan 模式）

### 第 1 步：访谈

像专业封面团队开需求会一样提问。**分两轮，每轮一组相关问题**，不要一次抛七个问题，也不要一问一答拖太长。用户答不出时给出推荐项并说明理由。

**第一轮（内容层）：**
1. 这期视频讲什么？已有标题或标题方向吗？
2. 分类标签选哪个？（从档案的标签集里选，给推荐：按主题自动判断）
3. 有没有要进画面的素材：工具截图、Logo、产品图、对比图？

**第二轮（画面层，基于第一轮答案给出具体建议再问）：**
4. 真人模式：表演方案选哪套？先按标题情绪查 `performance-library.md` 的主题映射表，再对照 `cover-log.md` 反重复，给出 **2-3 套互相差异大的完整表演方案**（每套 = 动作大类 + 表情 + 景别角度 + 场景 + 服装，不是同一姿势的微调），标注哪套与最近封面差异最大。／ 无人脸模式：画面主角用什么物件和场景？
5. 证据物用什么？（基于素材给方案；没有素材时建议一个真实物件或一处可信的操作瞬间）
6. 标题定稿 + 哪几个字换品牌色？（用户没标题时给 2-3 个候选，每个 6-14 字，并标出换色字）

快速模式：用户说"快速来一张"或只给主题时，两轮问题压缩为一轮——直接给出完整推荐方案卡，让用户说"可以"或改哪里。**压缩的只是提问，不是确认：仍必须等用户对方案卡回复同意后才能编译提示词和生图。**

### 第 2 步：封面方案卡

访谈完成后输出方案卡，**等待用户确认后才编译提示词**：

```markdown
## 封面方案
- 标题：[标题原文，换色字用【】标出]
- 分类标签：[分类]
- 表演：[动作大类+具体动作] | [表情] | [景别/朝向/机位] | [服装] ／ 无人脸模式：[主角物件+状态]
- 人脸参考：[主参考图文件名 + 为什么选它；辅助参考图文件名]
- 证据物：[具体物件及位置]
- 照片场景：[环境、光线、色调]
- 构图：纯黑信息栏（标题+标签）/ [品牌色]框照片区 / 主体突破框的方式
- 停留点：[箭头或圈注，至多一个；可以没有]
- 反重复：[动作大类与最近 2 张不重复；场景与上一张不重复；表情与上一张不同]
```

用户要求修改时只改对应项，重新出卡。

### 第 3 步：编译提示词

确认后，按固定模块顺序输出一条完整中文提示词（模块拼装规则见 `references/chinese-prompt-templates.md`）：

1. 画布与两区骨架（3:4、纯黑信息栏、[品牌色]圆角框）
2. 左上分类标签
3. 信息栏标题文字（原文 + 换色字 + 文字保真指令）
4. 照片区摄影指导（真人：身份参考 + 方案卡的全部表演参数：动作、表情、景别、朝向、机位、服装、场景、光线／无人脸：物件、场景、光线）
5. 证据物及其与主体的关系
6. 突破框关系
7. 质感（真实摄影、颗粒、调色）
8. 禁止项

### 第 4 步：生图（仅限用户明确要求）

先检测环境（见"生图双模式"）：

- **环境内有生图工具**（如 Codex 的 `$imagegen` / `image_gen`）：一次调用只生成一张图；真人模式先用可用的图片查看/输入能力加载主参考图和辅助参考图，再调用生图；提示词中必须写明"主参考图决定脸，辅助图只补充角度"。生成后立刻对照"自检清单"评审，把结果告诉用户。
- **环境内没有生图工具**：输出提示词导出包——
  1. 完整中文提示词（代码块，方便复制）
  2. 使用说明：比例设 3:4；真人模式提醒用户附上 `assets/faces/` 里的人脸参考图；推荐支持中文文字渲染的平台（即梦、豆包等）
  3. 请用户把生成结果发回来，再走第 5 步评审

### 第 5 步：评审与重试

逐项检查：

- [ ] 标题文字与方案卡原文逐字一致，无错字、漏字、重复字
- [ ] 换色字正确，只有指定的字是品牌色
- [ ] 文字全部在纯黑信息栏内，没有压到照片
- [ ] 品牌色圆角框存在且完整，照片在框内
- [ ] 主体（头/手/物件）突破了框沿
- [ ] 真人模式：是主理人本人（无身份漂移），表情是抓拍感不是证件照
- [ ] 真人模式：人脸相似度优先通过，尤其是脸型、眼镜、发型、眼距、鼻嘴比例和年龄感；若不像本人，即使构图好也判为不通过
- [ ] 照片有真实摄影感（光线、景深、颗粒），不是海报渲染
- [ ] 证据物具体可信，不是完整 dashboard
- [ ] 画面没有 REC、红点、红框
- [ ] 信息极简：除标题、标签、照片、至多一个箭头/圈注外没有别的元素
- [ ] 表演不重复：对照 `cover-log.md`，动作大类与最近 2 张不重复，场景、表情与上一张不重复
- [ ] 服装简洁轻便（短袖/薄上衣优先），不臃肿，不抢标题和品牌色的焦点

评审通过、用户认可后，在 `cover-log.md` 追加一行本次封面的表演记录。提示词导出模式下，评审对象是用户发回来的图；用户没发回图也认可方案时，照常记录日志。

文字出错是最高频问题。重试策略：缩短标题（≤10 字）、减少换色字（≤2 字）、在提示词里把标题文字单独引号强调并注明"逐字准确渲染"。同一方案最多重试 3 次（导出模式下即给出修正后的提示词请用户重试），仍失败则建议用户改更短的标题。

## 硬规则

- 提示词必须是中文，一条完整段落式提示词。
- 没有用户确认的方案卡，不得输出提示词；没有用户明确要求，不得调用生图。确认必须来自用户**看到方案卡之后**的回复——首条需求消息里的"直接生成"不构成确认。
- 标题 6-14 个汉字；换色字 2-4 个；只能有一组换色字。
- 信息栏内只允许：分类标签 + 标题。副标题默认不要；用户坚持时最多一行小字。
- 主体必须是画面核心，占框内高度 70%-90%。
- 每张封面至多一个箭头或圈注，可以没有。
- 默认不加任何 Logo；用户提供 Logo 素材时，Logo 作为照片区内的真实物件出现（如手机屏幕上、贴纸、实物），不悬浮在画面上。
- 六条设计定律和两区结构不接受用户自定义；品牌色、分类标签、人脸只从 `profile.md` 或当次输入读取。
- 真人出镜时，人脸保真优先于动作、场景、道具和视觉冲击；不能为了动作丰富而牺牲本人相似度。
- 无人脸模式必须由用户明确选择：人脸照片缺失时先主动向用户索要，用户明确说不出镜/提供不了，才能走无人脸；禁止静默降级。
- 表演反重复是硬规则：动作、表情、场景从 `references/performance-library.md` 选取——动作大类与最近 2 张不重复，场景、表情与上一张不重复。没有"默认姿势"——工作桌前指向屏幕只是十二分之一种动作，禁止成为事实默认值。
- 服装不强制轮换，但必须简洁轻便（短袖 T 恤、薄卫衣、衬衫优先），禁止臃肿厚重的穿搭，颜色不抢标题和品牌色的焦点。
