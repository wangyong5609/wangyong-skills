# CimiData 指定时间段公众号文章采集：官方接口、成本与推荐算法

> 抓取日期：2026-08-21（Asia/Shanghai）
>
> 范围：仅使用次幂数据官网及官网直接链接的官方 ShowDoc 项目；未调用任何次幂业务 API 或支付接口。
>
> 目标：指定公众号与起止时间，获取文章清单，并按需获取正文、互动或评论。

## 结论

公开 API 没有一个接口能同时接收“公众号 + 起止时间”。可编程且成本最低的主链是：缓存或解析 `wxid`，调用 `POST /api/v2/articles/history` 从最新页向历史分页，在本地按 `published_at` 筛选，只对命中区间且本地缺失正文的 URL 调用 `POST /api/v3/articles/detail`。历史列表报价 `0.05/次`，正文报价 `0.01/篇`。[历史列表接口](https://www.showdoc.com.cn/2265380957870963/10679051464081355) [正文接口](https://www.showdoc.com.cn/2265380957870963/11123545047367523) [API 价格](https://www.showdoc.com.cn/2265380957870963/11559023150418150)

`history` 只支持 `wxid` 和分页游标 `last_id`，不支持 `start_at`、`end_at` 或页码；文档称每次返回“最近 10 次发文数据”，`last_id=None` 表示末页。这里的单位写的是“发文次数”，不能擅自等同于 10 篇文章。[历史列表接口](https://www.showdoc.com.cn/2265380957870963/10679051464081355)

两个搜文接口都不能替代这条主链：数据库搜索仅接收 `keyword`；微信搜一搜仅接收 `keyword` 和 `page=1..5`。两者都没有公众号、`wxid` 或起止时间参数。[数据库搜文](https://www.showdoc.com.cn/2265380957870963/11106669898736966) [微信搜一搜](https://www.showdoc.com.cn/2265380957870963/11119847033359431)

官网另有“历史文章数据导出”，直接支持自定义时间范围，页面说明原价为 `50 元/年/账号，不足一年按一年计算`，等待 `10~60 分钟`；它导出文章统计与互动字段，但官网没有承诺包含正文 HTML，因此不能把它当作正文 API 的等价替代。[历史数据导出](https://www.cimidata.com/data/export) [官方导出说明](https://www.cimidata.com/article/Yl3wG3b6)

## 官方文档可信度

- **强证据**：次幂官网的 [API 服务页](https://www.cimidata.com/api-service) 直接把“开发文档”和“服务报价”链接到 ShowDoc 项目“次幂数据API接口文档”；本文的接口、参数、价格和错误码均以该项目为准。
- **中等证据**：导出页当前前端结算逻辑属于次幂官网一手页面，但优惠可能随时变化；付款前必须以页面最终显示金额为准。[历史数据导出](https://www.cimidata.com/data/export)
- **推导或工程假设**：成本公式、北京时间半开区间、缓存策略和早停条件是基于官方接口合同的设计，不是次幂对排序、时区或游标稳定性的承诺。

## 基础合同与计价口径

官方文档给出的主机是 `https://api.cimidata.com`。POST body 必须为 JSON，并设置 `Content-Type: application/json`。[官方 readme](https://www.showdoc.com.cn/2265380957870963/10159367712458941)

`POST /api/v2/token` 的 body 为 `app_id`、`app_secret`，返回 `access_token`，有效期 7 天；价格表把 token 标为免费。其他受保护接口把 `access_token` 放在 query 中。[获取 token](https://www.showdoc.com.cn/2265380957870963/10159368418053187) [API 价格](https://www.showdoc.com.cn/2265380957870963/11559023150418150)

报价页只写 `0.05/次` 等数字，没有在表头明确写币种；但次幂 API 服务页把可用余额显示为 `¥`，余额 API 又明确返回值单位为“分”，所以本文按人民币元解释报价。这个币种解释证据较强，但仍建议在首次真实调用前向商务书面确认。[API 服务页](https://www.cimidata.com/api-service) [查询余额](https://www.showdoc.com.cn/2265380957870963/10170271047086984)

公开官网没有写 API 最低充值额、开通费、充值套餐、余额有效期或退款规则。`99/298/698 元/月` 是网站会员套餐，官网没有说明会员费可充入 API 余额，不能把会员当作 API 的最低套餐。[API 服务页](https://www.cimidata.com/api-service) [网站会员](https://www.cimidata.com/price)

## 候选调用链与成本

定义：

- `R`：解析公众号的一次性成本。已有本地 `wxid` 为 `0`；已有该公众号任意文章链接并调用 `articles/info` 为 `0.02`；准确昵称调用 `accounts/detail` 为 `0.04`；模糊名称调用 `accounts/search` 为 `0.10`。同名搜索后若还要基本信息，应把两次成本相加。
- `P`：为了覆盖目标起始时间实际购买的历史列表页数。
- `N`：区间内唯一文章 URL 数；正文只计算本地缺失正文的 `N_body`。
- `C`：实际购买的评论页数。

| 结果范围 | API 成本（元） | 说明 |
| --- | ---: | --- |
| 仅文章清单 | `R + 0.05P` | 最便宜的程序化时间段结果 |
| 清单 + 正文 | `R + 0.05P + 0.01N_body` | 推荐默认链路 |
| 清单 + 正文 + 基础互动 | `R + 0.05P + 0.01N_body + 0.02N` | 阅读、点赞、在看 |
| 清单 + 正文 + 完整互动 | `R + 0.05P + 0.01N_body + 0.03N` | 再含评论数、分享数 |
| 上一项 + 每篇一页评论 | `R + 0.05P + 0.01N_body + 0.03N + 0.03N` | 评论默认不应开启 |

正文 API 的两种版本同价，应优先选只含正文的 v3；已经有历史清单时，不要为每篇改用 `0.02` 元的 `articles/info`，除非确实需要作者、原创标记或账号字段。[纯正文](https://www.showdoc.com.cn/2265380957870963/11123545047367523) [完整页面](https://www.showdoc.com.cn/2265380957870963/10894429678032029) [文章与账号](https://www.showdoc.com.cn/2265380957870963/11559060627371469)

### 与官网导出比较

导出页的文字合同是 `50 元/年/账号，不足一年按一年计算`。截至抓取日，页面前端对自定义范围实际按 `Y = ceil((end-start)/365天)` 计算，最多 12 年，并把当前优惠金额算为 `A × (30Y + 20)` 元、原价显示为 `A × 50Y` 元；其中 `A` 是账号数。该优惠来自当前官网结算代码，强度低于固定文字合同，可能变化，不能在支付前写死。[历史数据导出](https://www.cimidata.com/data/export)

导出明确包含阅读、点赞、在看、转发、留言、是否原创等统计；官方介绍还列出发布时间、标题、发文位置和文章链接，但没有承诺正文 HTML。[历史数据导出](https://www.cimidata.com/data/export) [官方导出说明](https://www.cimidata.com/article/Yl3wG3b6)

- 只要正文：API 为 `R + 0.05P + 0.01N_body`；导出后仍可能要为正文另付 `0.01N_body`。按一账号一年 50 元计算，只有历史遍历超过 1000 页时，导出才可能仅在清单成本上追平 API。
- 需要完整互动：API 为 `R + 0.05P + 0.03N`（不含正文）；当前导出候选为 `A × (30Y + 20)`。当 `R + 0.05P + 0.03N` 高于导出页面最终金额时，批量导出才可能更便宜。
- 导出是异步购买流程，官网写等待 `10~60 分钟`；公开页面没有给出可编程的任务提交 API，因此不适合需要自动化、增量和幂等重跑的采集器。[历史数据导出](https://www.cimidata.com/data/export)

## 推荐算法

### 1. 先查本地索引与覆盖区间

为每个 `wxid` 维护：规范昵称、别名、已知 `published_at` 最早/最晚值、已覆盖的半开时间区间、文章 URL 指纹、正文/互动获取状态、历史页指纹和游标检查点。若请求区间已经被本地 metadata 索引完整覆盖，列表成本为 0，只补缺失正文或互动；区间部分覆盖时，只采缺口。

游标跨天或跨运行是否稳定，官网没有承诺。缓存 `last_id` 只能作为加速提示：恢复后先验证返回页指纹与时间边界；不匹配就放弃旧游标，从最新页重新走，并由页数预算止损。[历史列表接口](https://www.showdoc.com.cn/2265380957870963/10679051464081355)

### 2. 最便宜地解析公众号

1. 直接输入 `wxid` 或命中本地 `nickname -> wxid` 缓存：`R=0`。
2. 已有该账号文章链接：用 `articles/info` 取 `wxid`，`R=0.02`。
3. 只有准确昵称：尝试 `accounts/detail`，`R=0.04`。
4. 名称模糊或同名：最后才用 `accounts/search`，`R=0.10`，让调用方从约 20 个候选中确定账号后缓存结果。

官网也说明可从文章源代码中的 `var user_name` 找到 `wxid`；如果调用方已经有文章页面并能本地解析，可以省掉付费解析调用。[历史列表接口](https://www.showdoc.com.cn/2265380957870963/10679051464081355)

### 3. 用北京时间半开区间筛选

把用户日期转换为北京时间半开区间 `[start, end)`；例如“2026-08-01 到 2026-08-07”应转换为 `[2026-08-01 00:00:00, 2026-08-08 00:00:00)`，避免末日 `23:59:59` 和微秒边界问题。

官方 `published_at` 示例没有时区偏移，文档也没有声明时区。把它解释为 Asia/Shanghai 是本采集器的工程假设，必须在首次受控验证后记录；在确认前，产物元数据应保留原始时间字符串和 `time_zone_assumption=Asia/Shanghai`。[历史列表接口](https://www.showdoc.com.cn/2265380957870963/10679051464081355)

### 4. 从最新向旧分页，本地过滤

1. 请求第一页 `{wxid}`；后续页传上一页的 `last_id`。
2. 页面到达后先检查 cursor/page fingerprint 是否重复，再处理 `items`。
3. 对每篇文章规范化 URL 并去重；长链接优先以 `__biz + mid + idx + sn` 组成稳定键，短链接或字段不完整时保留规范化完整 URL，不能因激进去参数而误合并不同文章。
4. 先写 metadata，再比较 `published_at`：`t >= end` 的新文章跳过但继续翻页；`start <= t < end` 的文章进入候选；`t < start` 仅用于判断早停。
5. 只有在当前运行中已连续验证页面时间非增（新到旧），且整页都早于 `start` 时，才以“跨过 start”早停。官网只描述“最近”和“更多历史”，没有承诺严格排序；一旦出现逆序，禁用该早停并继续到空游标或预算上限。

四个强制停止条件：

- `last_id` 为 `None`、空或缺失：正常到达末页。
- 下一游标已经见过，或页面 URL 指纹集合重复：异常停止，标记 `partial/repeated_page`，避免死循环。
- 已跨过 `start` 且本次运行的倒序不变量一直成立：正常早停。
- 实际调用页数达到 `max_pages` 或预计下一页将突破 `max_cost`：预算停止，标记 `partial/budget_exhausted`，不得声称完整覆盖。

### 5. 只为唯一命中 URL 购买正文

列表结束后，对 `[start,end)` 内候选按 URL 指纹去重；先查本地正文哈希，只对缺失或明确要求刷新者调用 v3 正文接口。正文成功后再原子提交文章记录与 coverage；失败不能把该区间标为正文完整。[正文接口](https://www.showdoc.com.cn/2265380957870963/11123545047367523)

互动和评论也是候选确定后再按需买。评论文档没有公开 `buffer` 的请求传法，因此默认只允许首屏，或在商务书面确认分页合同后才启用多页。[评论接口](https://www.showdoc.com.cn/2265380957870963/11480368861624590)

### 6. Dry-run 成本上下界

执行前强制用户给出 `max_pages`、`max_articles`、是否正文、指标档位与 `max_comment_pages_per_article`。定义：

- `P_min`：本地 coverage 推导的最少新增列表页；完全覆盖为 0，否则至少 1。
- `P_cap`：本次允许的最大列表调用次数，包含文档允许的那一次首次失败重试。
- `N_known`：本地已知且缺正文的命中文章数。
- `N_cap`：用户允许购买正文/指标的最大唯一文章数。
- `M`：每篇增强单价；无增强为 0，基础互动为 0.02，完整互动为 0.03，再加允许的评论页数乘 0.03。

```text
lower_bound = R + 0.05 * P_min + 0.01 * N_known + M * N_known
upper_bound = R + 0.05 * P_cap + 0.01 * N_cap   + M * N_cap
```

如果不需要正文，把 `0.01 * N` 项置零。列表完成后，用实际 `P_actual` 和去重后的 `N_missing` 重新生成第二次 dry-run，获得正文/互动阶段的精确上限，再执行逐篇请求。官网没有说明失败请求是否扣费，因此上界按每次尝试都可能计费保守预算。

### 7. 当日接口只作为严格特例

只有同时满足以下条件才用 `articles/current` 替代首个 history 请求：目标区间完全落在当前北京时间自然日内；只需要当天发文；返回字段足以完成所需语义；不需要跨日续页；本地验证没有缺条。此时 `0.04/次` 比 history 的 `0.05/次` 省 `0.01` 元。只要区间跨日、需要历史完整性或当日结果存在疑问，就选 history，不为一分钱牺牲语义完整性。[当日文章](https://www.showdoc.com.cn/2265380957870963/10159368970676804) [API 价格](https://www.showdoc.com.cn/2265380957870963/11559023150418150)

## 错误处理与限制

官方错误页列出：`400/1002` 参数错误、`1004` 数据不存在、`4203` token 无效、`4204` token 过期、`4205` appid 失效、`4300` 账号未加入资源库、`5022` 内容异常、`5100` 评论获取失败、`6020` 余额不足、`6021` 阅读量获取失败。错误页同时声明“具体错误以实际返回为准”。[错误码](https://www.showdoc.com.cn/2265380957870963/10159372243276268)

- `4204`：重新获取 token 后只重放当前未提交的幂等读取。
- `6020`、`4205`、`4300`：立即停止，不自动充值、不盲目重试。
- `400/1002`：记录脱敏请求结构并停止修正；相同参数重试没有意义。
- history、account detail、current 文档明确提到首次未收录时可等待后重试；最多一次，并把这次尝试预留进成本上界。[历史文章](https://www.showdoc.com.cn/2265380957870963/10679051464081355) [公众号详情](https://www.showdoc.com.cn/2265380957870963/10159370848636686) [当日文章](https://www.showdoc.com.cn/2265380957870963/10159368970676804)

## 仍未确认，不能编造成承诺

- 历史页严格按 `published_at` 倒序，以及同一时间戳的稳定次序。
- `last_id` 的有效期、跨运行稳定性、并发安全和是否绑定 token。
- 历史接口最早可追溯日期、QPS、并发上限和单账号每日限额。
- `published_at` 的时区；本文的北京时间处理是显式工程假设。
- “最近 10 次发文数据”究竟是 10 个群发批次还是 10 篇文章。
- history 首次错误重试、其他失败响应是否扣费。
- API 最低充值额、开通费、充值套餐、余额有效期和退款规则。
- 余额查询是否收费；它未列入价格表。
- 评论下一页如何提交 `buffer`。
- 导出是否提供正式可编程 API、导出的全部列、当前优惠持续时间。

这些缺口不会阻止实现一个受预算保护的版本，但“完整覆盖”只能在游标正常结束或经验证的倒序早停后声明；因页重复、排序异常、错误或预算停止时必须返回 `partial` 与明确原因。
